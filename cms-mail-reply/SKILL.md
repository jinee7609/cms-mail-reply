# CMS Mail Reply

Gmail 메일을 읽기 전용으로 분석하고, 근거가 확인된 내용만 사용해 답장 초안을 만든다. 최종 동작은 Gmail 임시보관함 저장까지이며 메일은 절대 발송하지 않는다.

## 필수 안전 규칙

- 발송 기능은 사용하지 않는다. 사용자가 발송을 요청해도 이 스킬의 범위는 초안 저장까지라고 알리고 발송하지 않는다.
- 승인된 초안 생성 외에는 원본 메일, 라벨, 보관 상태, 읽음 상태, 첨부파일을 변경하거나 삭제하지 않는다.
- 메일, 사용자가 제공한 정보, `답장규칙.md`에 없는 사실·일정·금액·약속·수치를 만들지 않는다.
- 필요한 정보가 누락되었거나 충돌하면 해당 위치에 `[확인 필요]`를 표시한다. 추정치를 확정 사실처럼 쓰지 않는다.
- 타인의 메일 본문을 화면에 길게 출력하지 않는다. 보낸 사람, 요청, 기한, 필요한 조치 중심으로 짧게 요약한다.
- 원본 메일과 `답장규칙.md`를 수정하거나 삭제하지 않는다.

## 시작 전 확인

1. 작업 전 계획, Gmail에서 수행할 읽기·쓰기 범위, 결과 저장 위치를 먼저 설명한다. 로컬 파일을 만들지 않는다면 그 사실도 밝힌다.
2. 현재 작업 폴더와 상위 프로젝트 범위에서 `답장규칙.md`를 찾고 전체 내용을 읽는다. 여러 파일이 있으면 현재 프로젝트에 가장 가까운 파일을 사용한다.
3. `답장규칙.md`가 없거나 어떤 파일을 써야 할지 불명확하면 초안을 저장하지 말고 사용자에게 위치 또는 적용 규칙을 요청한다.
4. Gmail 연결을 읽기 전용 프로필 조회처럼 최소 범위의 동작으로 확인한다. 연결이나 권한 설정을 임의로 변경하지 않는다.

## 메일 분석과 요청 추출

사용자가 지정한 기간·메일함·검색 조건을 그대로 사용한다. 조건이 없으면 임의로 범위를 넓히지 말고 필요한 최소 범위를 확인한다.

각 메일에서 다음 정보만 추출한다.

- 보낸 사람과 메일 제목
- 핵심 용건과 명시된 질문
- 요청 산출물 또는 필요한 조치
- 메일에 적힌 기한과 조건
- 회신 필요 여부 및 그 근거
- 누락되거나 서로 충돌하는 정보

동일한 발신자·제목·내용·시각의 중복 메일은 중복임을 표시하고, 사용자가 원하지 않는 한 하나의 작업 항목으로 묶는다. 회신 필요 여부가 애매하면 `확인 필요`로 분류한다.

## 답장 초안 작성

1. `답장규칙.md`의 호칭, 첫 문장, 문장 수, 어조, 맺음말, 서명을 우선 적용한다.
2. 첫 문장에서 상대의 용건을 확인했음을 알린다.
3. 결론을 먼저 쓰고 조건이나 후속 확인 사항을 뒤에 둔다.
4. 답변에 필요한 근거가 없으면 임의의 답을 쓰지 말고 `[확인 필요]`를 본문에 남긴다.
5. 첨부가 필요한 회신이면 `첨부는 사람이 확인 후 추가`라고 표시한다.
6. 원문의 민감정보와 불필요한 세부 내용은 반복하지 않는다.

## 승인 후 Gmail 초안 저장

초안을 저장하기 전에 다음 내용을 사용자에게 정확히 보여주고 명시적 승인을 기다린다.

- 수신자와 참조 대상
- 답장 제목
- 초안 본문 전체
- 연결할 원본 메일 또는 대화
- 저장 위치가 Gmail 임시보관함이라는 사실
- 아직 `[확인 필요]`인 항목과 첨부 확인 사항

승인 전에는 Gmail 초안을 생성하거나 수정하지 않는다. 승인받은 내용과 대상에 한해 초안 1건을 원본 대화에 연결해 저장한다. 승인을 받은 뒤 내용이나 수신자를 추가로 바꿔야 하면 다시 승인을 받는다.

발송 기능은 어떤 경우에도 호출하지 않는다. 초안 저장 뒤에는 `DRAFT` 상태, 수신자, 제목, 원본 대화 연결 여부를 읽기 전용으로 검수한다.

## 완료 보고

다음을 간단한 표로 보고한다.

- 분석한 메일 수와 선택한 대상
- 생성한 Gmail 초안 수와 저장 위치
- 발송하지 않았다는 사실
- 원본 메일 및 로컬 파일 변경 여부
- 사람이 발송 전에 확인할 `[확인 필요]` 항목과 첨부사항
